# Unigentamos authenticated product design

## Approved direction

The product is a composed, precise working environment. Record identity, typography, useful density, and continuity provide its character. People establishes identity-first clarity; Projects proves the shared directory/detail system. The approved public landing page is preserved.

## Information hierarchy

Every workspace exposes its identity, current view and one authoritative count, then useful records. One primary action belongs to each task context. Search, filtering, sorting and view selection form one toolbar. Advanced controls reveal on demand. Secondary metadata follows the record rather than competing with it. Notes centers authored reading; Media centers real images; Finance centers the active transaction scope; Map centers geography; Calendar centers time. Actual scheduled commitments and inferred review suggestions remain distinct.

No dashboard heroes, obligatory metric rows, equal-weight card grids, gradient placeholders, glass, glow, decorative icon tiles, repeated counts, tiny monospace prose, fake progress or disconnected actions. Missing imagery uses a neutral semantic fallback. Relevant labels remain visible.

## Shared geometry and type

- Spacing unit: 4px. Related facts 4–8px; control groups 12px; content groups 16px; sections 24px; major context changes 32px.
- Header offset: --app-content-offset, 64px desktop and 56px compact. All module and overlay placement derives from it.
- Gutters: 24px desktop, 20px tablet, 16px phone. Desktop controls 40px, primary touch controls at least 44px. Radius 8px controls, 12px menus, 16px dialogs.
- Plus Jakarta Sans: workspace 28/34 (phone 24/30), record 24/30 at 650, sections 18/24 at 600. Headings may use -0.02em tracking.
- Inter: rows and UI 14/20, secondary 13/18, labels 12/16, input 16/22 and prose 16/25. Body tracking normal. Weight primarily 400–600. Reading measure 65–75 characters.
- Inconsolata only for technical identifiers. Comparable numbers use Inter tabular numerals, right alignment and consistent precision.
- Content separates through alignment, proximity and whitespace. Shadows belong to floating surfaces, not every section.

## Palette and recognizable objects

Before creating or refining a module, reference Personal > Style Guide and `dashboard/lib/design-system/color-system.ts`. Reuse the shared Ink, text, surface, typography and border tokens; use the owning module primary palette for primary actions and selection, and its secondary palette for supporting controls. Calendar pairs smoky indigo with Slate 100 #E5E9EE, Slate 500 #788392 and Slate 700 #515D6B. Use Slate 700 for readable small accents and white-on-slate labels; reserve Slate 500 for decorative accents and outlines. Do not invent local colors or replace saved calendar/group colors to style interface controls.

Ink #102026, body #23383F, secondary #60747C, canvas #F4F7F5, surface #FFFFFF, inset #FBFCFB, divider #D5E2E7, primary action #133C5E. Existing module palettes identify their module, not operational state. Map uses light leaf green #B1D68A, dark readable ink #50752F and quiet #F3F8ED; Calendar uses smoky indigo #59518B with #F3F2F9. People utility controls use secondary olive #5A6040 with #E4E8D8. Essential text requires 4.5:1 contrast. Status combines meaning with text or an icon, not color alone. Command Center module sources use white surfaces and canonical module icons and colors. The shared assistant uses the same navy treatment in every workspace.

UnigentamosIcon is the shared registry: 24-unit drawing grid, rounded joins, 16px inline, 20px controls, 24px navigation. Preserve the hand-selected Projects, Notes, People, Media, Personal, Reviews, Resources, Finance and Vault assignments. Their saved selections take precedence over registry defaults; redesigns and registry additions must not reset them. Every new icon role must be registered with five distinct selectable Style Guide options and included in the generated sprite. New module entries are appended to saved style guides without replacing existing assignments or palettes. Recognizable portraits, logos, source previews, actual thumbnails and chosen project marks take precedence over generic decoration.

## Responsive and accessible behavior

Full navigation appears only when it fits; a labeled-for-accessibility icon strip takes over before collision and scrolls horizontally on narrow phones. A persistent selection box moves between modules and blends to their colors without an underline. Clicking the home logo preserves navigation while playing the landing-page orbit spin. Directory/detail persists on wide screens, then becomes a dismissible sheet or page. Preserve filters, directory scroll and return position. Phone useful content should begin near the first 260px at 390x844. No horizontal document overflow. Menus portal out of clipping ancestors; dialogs trap and restore focus, expose Close, and retain visible actions with the keyboard. Icon-only actions have names. Forms preserve drafts and report errors at the operation that failed.

## Motion

Shared tokens: press 80ms, quick 120ms, standard 180ms, panel 260ms, context 320ms, explicit map focus up to 450ms. Arrivals use cubic-bezier(.22,1,.36,1); exits are shorter. Pointer dragging tracks directly, with explicit insertion/drop targets. Hover changes surface without moving labels. Focus appears immediately. Small confirmations occur in place. Save and upload states represent real work. Selection updates immediately; large content does not slide across the entire viewport. No perpetual decorative movement, repeated page entrances or staggered row animations.

The navigation selection uses a physical spring (stiffness 280, damping 30, mass 1.2), preserving velocity when the target changes. Color blends independently without overshooting. System and previously saved application reduced-motion settings remove large motion, zoom, spring and smooth scrolling, retaining confirmations, focus and functional parity. The navigation does not expose a Reduce motion button.

## Domain and quality constraints

Private objects retain canonical ownership and stable IDs, with encryption, audit, version history, validation and conflict boundaries. Local saved and synchronized are different states. Calendar imports are inbound only; edits remain overrides, failed refresh never removes events. Trips retain Personal ownership, with Map and Calendar projections. Media retains one asset identity and encrypted chunks. Public provider caches never contain private canonical records.

Calendar fits the viewport, defaults to 8 am–10 pm, and exposes earlier/later hours with event-count indicators and direct add actions. Hourly separators and centered labels stay aligned as the grid resizes; editing, dragging and keyboard resizing support five-minute increments. Weekends, completed tasks and a wider current day are view options. Month navigation opens from the heading. Event editors keep start/end date-times together, description near the top, quiet all-day controls, numeric reminder offsets and recurrence intervals, and one canonical object-link section. Icon/color groups belong to calendars and event group assignments use the existing encrypted synchronization and conflict contracts.

Calendar day headers stack a full weekday label in Inter above a 24px Plus Jakarta Sans date, centered on the day column; narrow week columns use two-letter labels. Today uses a quiet indigo surface and a rounded date marker. Solid vertical day boundaries are stronger than the dashed horizontal hour guides. The heading opens one indigo month/day picker with keyboard navigation and focus return. Day widths, time rows and event positions share a damped layout spring (stiffness 340, damping 36, mass 0.9). Date navigation retargets one live calendar with a small directional arrival; expanded-hour settings persist across views. Both saved and live system reduced-motion preferences suppress movement.

Event editor sections separate through spacing rather than rules. All day, Repeat, and Reminder use the same indigo checkmark treatment with native keyboard behavior. Repeat and reminder inputs remain visible and editable while unchecked; toggling preserves the draft settings. The location icon and address/meeting-link field sit below the description. An icon opens the shared object search, including place search, with canonical links and duplicate exclusion. One group-color panel shows every group and saves the palette together using the calendar's existing conflict protection. Start/end fields stack on small phones.

Event start/end controls open a custom indigo popover with Date and Time tabs, a Monday-first month grid, a month/year jump view, and hour/minute/AM–PM columns. Selected dates, tabs and times share the Calendar spring; month and pane changes retarget one live scene. The popover enters and exits from its trigger, remains inside the viewport, and restores focus without dismissing the event editor. Five-minute choices preserve imported minute precision until explicitly changed. All-day end dates display inclusively while retaining the canonical exclusive end date. Event wall-clock values and time zones remain separate; reduced-motion settings remove movement.

Week and day headers show all-day events and linked records by name in compact, wrapping cards. Events use their calendar/group color and icon and open the actual event; linked cards use their owner's module color and route. Multi-day events appear on every included day, excluding the canonical end date. The header grows with the cards and the hourly grid measures the remaining space, keeping labels, drag positions and events aligned. Dense headers scroll within their own list without opening a count menu or extending the page.

Calendar event previews include compact circular portraits of linked people, resolved from current People records, with initials for missing photos and a remaining-person count in dense previews. Linked-person chips in event details retain both the portrait and the canonical profile link. Birthdays project annually from active People records, including birthdays with no recorded year; February 29 stays on its recorded date. System birthday and holiday cards open explanatory details rather than editable copies of their source records.

Calendars owns visibility controls, birthday visibility, and a Holidays & dates panel. Country calendars start with United States public holidays and common observances; every supplied holiday can be enabled or hidden, with separate custom annual or one-time dates. The date-holidays rules run on the server without sending private data to an external service. Coverage is explicitly national, with regional variation noted. Preferences and custom dates belong to the native calendar and retain encrypted synchronization, validation, and stale-write protection.

Calendar uses one desktop command row for its title, period navigation, search, view, options, calendars and Add event. It reserves a draft slot beside the date, with a fixed draft row on phones, so opening and closing details never moves the grid. Period arrows use centered square controls; view choices combine icons and text. Hour-expansion controls use Calendar Slate 100, while Early event and Late event use light indigo Primary 100, without divider rules. The current-time line uses translucent Slate and its tabular AM/PM badge uses translucent Slate 100 with shared Ink text; secondary interface accents and placeholder portraits use Slate surfaces and shared Ink text, while saved event-group and calendar colors retain their meaning. Calendar forms use 12px labels and 13px input text on desktop, retaining 16px editable fields on phones to avoid focus zoom.

The date heading opens a Day / Week / Month / Year navigator with an always-visible Today action. Day lists the year's months, Week lists Monday-first ISO weeks, Month lists twelve months, and Year pages through years. Selecting a date switches the main calendar to the same scale. Year shows twelve interactive mini calendars with event indicators; month headings open Month and dates open Day. Agenda groups commitments by date, with a consistent time column, centered icons and linked-person portraits. View options group Widen today and Show weekends, then Display completed tasks and Linked work and trips, then a searchable custom time-zone control.

Calendar visibility, holiday choices and custom-date toggles use native keyboard-accessible indigo checkboxes. Settings rows align their icon, name and checkbox horizontally. Country menus use the existing local flag sprite and a thin indigo scrollbar; nested selects portal into their owning dialog so wheel scrolling remains available. Holiday rows give the date a compact month/day badge and keep classification secondary. Calendar names and colors include birthdays, every selected country and custom dates, stored as native-calendar observance preferences. Custom dates may be all-day or timed, with an explicit owning time zone, inclusive start/exclusive end and annual or one-time recurrence.

Map data uses explicit geographic scope, numeric legends and region comparisons. World Bank country data and US ACS state/county/tract data are separately labeled; the latter can use Esri's public ACS distribution without account setup. City/town estimates use an official 2020–2024 Census summary-file extract with source hashes and a reproducible refresh script, joined by GEOID to matching TIGERweb boundaries. Unmatched estimates remain in the table and are disclosed. Combined US layers must share geography and release vintage; missing values are never zero. Range filters combine with all/any matching, and saved views retain those filters. Quantile bands improve comparisons across skewed populations; equal-range scaling remains available. Spherical world boundaries are clipped at the antimeridian before rendering. Required map attribution is available through a compact information control.

Finance retains established zero-based chart semantics, guarded operations and explicit historical coverage. Missing history is never zero activity. Unavailable provider capabilities receive a precise explanation outside primary working actions.

Review uses real dense and incomplete fixtures, all viewport classes, keyboard/focus, reduced motion, save/reopen/sync, screenshots and interaction recordings. Desktop simulation does not establish physical iPhone/iPad Safari behavior. Production activation and deployment require later release authority.

Calendar view labels and glyphs are vertically centered as flex rows, with a dedicated Month grid icon. View-option groups maintain equal visual separation. Calendar visibility updates immediately with animated checkmarks and quiet selected surfaces, while ordered saves retain version checks and restore confirmed values on failure. Holiday date chips are darker than hovered rows; holiday and country scrollbars use rounded thumbs with transparent tracks. Respect reduced-motion preferences.
