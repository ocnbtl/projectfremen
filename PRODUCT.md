# Unigentamos product context

## Product

Unigentamos is Ocean's private, local-first operating system. It brings people, notes, resources, projects, personal operations, reviews, finance records, media, and the Vault into one coherent workspace that remains useful across Windows, MacBook, iPhone, and iPad.

## Core promise

- Every module and the Vault work with the same canonical records, not mirrored copies.
- Changes can be made in the purpose-built module view or the simplified Vault view and then sync across devices.
- Records remain available offline where the device policy allows it, with version history and recoverable conflict handling.
- Copy should be direct, concise, and human. The interface should explain what matters without exposing implementation vocabulary.

## Primary user and use

The primary user is Ocean, operating a large personal and business knowledge system from a Windows master device and Apple secondary devices. The product is moving from setup into sustained real-world data entry, so responsiveness, information hierarchy, trust, and low-friction capture are release-critical.

## Product boundaries

- Preserve authentication, authorization, audit, encryption, offline ownership, sync, and version-history boundaries.
- Finance is a records and planning workspace. No bank connection, payment execution, or unintended financial action is authorized.
- Media may remain desktop-resident and sync on demand to secondary devices.
- Backup to additional storage is planned later; the current release must not pretend that external backup exists.
- Avoid paid-platform dependency where the local-first architecture can provide the required capability.

## Brand and experience

Unigentamos should feel like a calm, capable operations desk: warm enough to be personal, disciplined enough to trust with important work, and dense enough to use every day. One shared shell and visual language should connect Command Center, People, Projects, Resources, Personal Ops, Finance, and Vault while allowing each module's content model to remain specialized.

## Accessibility and device expectations

- Responsive from 390px mobile through tablet and wide desktop.
- Touch targets remain comfortable on iPhone and iPad.
- Navigation, search, and workspace controls must not overlap at intermediate widths.
- Keyboard navigation and visible focus remain first-class on desktop.
- Reduced-motion preferences are respected.

This file records requirements explicitly stated across the active project conversation and constraints already represented in the repository. It does not claim external user research or production behavior that has not been verified.
